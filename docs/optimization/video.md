# 2. 影片解码、动态 CG 和音画时序

## 解码、首帧与时钟

| 版本 | 优化 |
|---|---|
| `806dd9f`、`2f76b26` | 通过 FFmpeg NVTEGRA 使用 NVDEC。为原片头、片尾与动态 CG 编码 H.264，保留原音频包。Matroska 载荷回填原封包。原版 Ogg/Theora 仍可软件播放。 |
| `6822bc7`、`f364ad4` | 在后台准备影片、首画面和 PCM。画面提交后启动影片声道，以混音器采样游标推进画面。 |
| `09d736e` | 按音频时钟推进，只转换最后一张到期画面，避免对略过的帧反复转色。 |
| `c6b5b0d`、`dcc8bd5` | 互动绘制和剧情捕获分小批追帧。图鉴差分由后台准备，快速选择保留最近请求，延续原有叠化。 |
| `18cf579`、`75116f5` | 动态循环优先 seek/flush 复用解码器。根据首个可见轨与实际媒体成员预热首帧。 |
| `f857a3a` | NVTEGRA/VIC 的 NV12 下载使用对齐布局，失败时沿用 FFmpeg 分配路径。 |

Mac 原包片头 50 帧、片尾 1,960 帧均自然结束。以混音游标和提交画面独立比较 360 个 PTS 样本，全部命中对应源帧。原版与重打版的 PCM 逐字节一致。一次 Mac 原包冷/预热对照中，片尾首帧 117.317→48.325 ms。

## NVDEC 与 deko3d 共用画面

解码出的原始 1280×720 NV12 表面映射为 deko3d 的亮度、色度图像。GPU 在纹理区域转色，后续沿用图层位置、透明度、采样和混合。帧与底层映射持有至 GPU 完成相关读取。

- `5d8b903` 接通片头和片尾。原包各八帧的宿主数值与 libswscale 对照最大差一个色阶。
- `73804c9` 接通符合条件的剧情动态 CG 和首帧预热。同一画面支持多个不同时间的影片纹理。Mac 用原包 H.264 和模拟映射验证多帧身份、混合、2D/3D、回退和解码器退出。Switch 构建确认内嵌对应 DKSH。

有裁剪、其他解码格式或不兼容的布局沿用原下载和转换。CPU 合成需要画面时按需取得像素。设备上的直传像素、连续播放稳定性和性能待验。映射思路参考 [wiliwili](https://github.com/xfangfang/wiliwili)。

## 生命周期和恢复

- `0489c2b` 内嵌影片硬解报错后保留上一画面，软件解码分批追上当前时间。
- `1ae5d60` 保留 FFmpeg NVTEGRA 共享驱动引用，直到影片和预读线程都已关闭。
- `77775a7` 独立影片硬解失败时从临近关键帧软解并保持原音轨时钟。Mac 片尾约 77 秒处注入故障后，解码 87 帧恢复，随后六张参考图像一致。

旧 Switch 日志确认内嵌 H.264 已产出硬件帧，随后报 Horizon 2001-0114。具体无效句柄仍待定位。
