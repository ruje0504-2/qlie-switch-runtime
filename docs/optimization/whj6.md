# 5.《美少女万華鏡異聞 雪女》专用优化

[返回目录](README.md)

《雪女》由 `QLIE_GAME=whj6` 构建。剧本和动画以 1920×1080 为逻辑坐标，运行时映射到 1280×720，呈现上限为 60 Hz。WHJ6 默认使用 deko3d，并保留 CPU 合成作为对照。影片尺寸和素材分卷的制作方法见[项目说明](../../README.md)。

## 雾气、飘雪和图层合成

| 场景 | 实现 |
|---|---|
| 老鹰和移动雾气 | 单色雾气使用逐像素独立采样，在同一像素里完成原顺序的双线性插值和 Screen 混合，并复用此前已经合成的图层。`999cb5a` 去除了雾气计算着色器的工作组共享内存和同步屏障，`b728715` 增加采样版的 GPU 队列错误与雾气图块记录。 |
| 雪人和同类 Overlay 叠加 | 无遮罩的 Overlay 层交给简单运动内核，按原图层顺序和整数混合公式计算。透明区域由图块覆盖检查裁剪。具有明确布局的 Screen 视频和灰度 Hard Light 层分别走专用路径。`b83ee18`、`6f27a25`、`970d8b6` |
| 标题雪景和章节卡 | 标题使用预读的雪景背景与首帧，GPU 合成适用的雪层和底图。章节卡提前准备首次可见的飘雪轨，按原时间放出第一帧。`f4c88fe` |
| 多层全屏暴风雪 | 专用合成核从常量缓冲读取绘制命令，按图层顺序完成 Screen 混合，跳过已确认纯黑的影片图块。每层风雪按需读取 3–4 个参数。 |
| 后段放大的灰度雪幕 | 识别两层 960×540 的不透明灰度雪幕，复用雾气的单通道双线性采样。按图层数据选择，后续同类场景自动复用。该优化已通过本地像素对照，实机帧率待确认。 |

正式构建通过 `tools/build_deko_shader.py --blizzard` 生成专用内核，并补齐变延迟指令的依赖等待。此步骤只作用于雪女的暴风雪内核。绘制命令超过常量缓冲容量时使用既有合成路径。雾气与灰度雪幕共用 `shaders/raster_gray.glsl`，字形缓存和正文增量渲染继续使用共用运行时，雪女负责自身的字体槽位映射。

本次本体 NSP 使用 1280×720 呈现和 `1.0.1` 配置，正式构建关闭诊断采样。独立探针中的逐阶段 GPU 等待用于排错，正式路径按常规帧提交。

Switch 采样版 `b728715` 在老鹰页 `y01-01.s:2383` 记录到切入时 55 帧，随后五次采样均为 60 帧。当时的全屏雾气合成约 7.3 ms，运行继续推进到后续剧情。同版晚段雪景 `y03-03.s:2018` 复看稳定后采样为 59–60 帧，切入附近一次全屏合成用时 17.7 ms，末尾 `y03-03.s:2161` 连续 13 次采到 60 帧。雪人页 `y03-01.s:97` 的 `e79bbf5` 实机日志有 60 帧样本，切入和叠层变化时仍有 36–51 帧样本。

Mac 离屏对照覆盖雪人和五个老鹰相关页面。通用合成与专用内核共比较 360 帧，逐像素一致。

后段暴风雪 `y05-01.s:4419` 和 `y05-01.s:4437` 在 Switch 采样版 `c4c7cb9` 持续约 25 帧，GPU 合成约 35 ms，四路 NV12 转色约 4–5 ms。独立暴风雪内核 `19aacea` 读第 14 号存档进入 `y05-01.s:4437` 时，首批 3600 个图块触发 GPU 队列错误。取消共享内存与同步屏障的 `e187b2b` 在同一位置复现。两次日志均记录到存档恢复成功、首批视频帧就绪和 GPU 队列错误。为同一内核加上驱动日志后，实机报告编号 `31`、错误类型 `1`，读取 GPU 虚拟地址 `0x0` 时发生页错误。恢复既有运动内核的 `65d1dde` 通过同一存档的实机复测，剧情推进至 `y05-01.s:5082`。暴风雪满屏合成仍约 25 帧，合成约 35.2 ms，四路 NV12 转色约 4.4 ms。[deko3d 错误字段定义](https://github.com/devkitPro/deko3d/blob/master/source/gpu_error.cpp#L31-L40)

把独立合成的输出改写到保留缓冲后，第 14 号存档仍触发页错误。该帧四路 NV12 转色的 GPU 时间戳完整，用时 3.943 ms。首批合成结束时间戳缺失，驱动报告读取地址为 `0x200020000`。

同一着色器加上 GPU 地址映射日志后再次复现，读取地址为 `0x20000`，当时的映射中没有该地址。十二条绘制命令的像素范围与 Screen 覆盖表均位于已绑定的源缓冲 `[0x505a40000, 0x509a40000)`。两次故障地址的低 32 位都是 `0x20000`，与队列工作缓冲基址 `0x500020000` 的低 32 位相同。仍需定位生成该地址的 GPU 读取。[deko3d 队列工作缓冲分配](https://github.com/devkitPro/deko3d/blob/master/source/dk_queue.cpp#L28-L43)

原生反汇编中，最早的依赖槽重叠位于 `0x3B0` 和 `0x3B8`。这两条 `LDG` 读取绘制命令的 `meta.zw`，分别是绘制标志和不透明度。调度排查版 `e187b2b-strict-deps` 只改变 12 组控制字，保留 DKSH 头和 546 个指令槽，静态检查发现的依赖槽重叠由 16 处降至 0。第 14 号存档的 90 帧离屏对照逐像素一致。Switch 实测仍在首批 3600 个图块合成时触发页错误，读取地址为未映射的 `0x3000c0000`。四路 NV12 转色耗时 4.400 ms，日志没有完成合成的暴风雪帧。这份日志没有提供故障指令的位置。

复跑调度排查版时，首批 3600 个图块再次报 GPU 页错误，读取地址变为 `0x200000000`。两次 Switch 系统错误报告均确认了应用日志中的读取地址，报告字段没有指令地址。该版实际嵌入的着色器共 33 条显式全局加载指令，使用图块、绘制命令、源和目标四个绑定。四个绑定的地址高 32 位均为 `5`。按绑定有效的前提，显式加载地址的高位由该值与低位进位组成，无法从静态指令和已知绑定确定是哪条读取产生了实机故障。

第 14 号存档的 GPU 指令探针 `e187b2b-native-pc` 在第一条图块头读取 `0x38`（`LDG.E.B32 R5, [R0]`）前留下 95 条记录，采到的读取地址均落在图块缓冲内。队列日志和 Switch 系统错误报告确认，本轮在未映射的 `0x544300000` 发生写入页错误。探针为记录加载前后状态增加了全局写入，因而这轮的待完成计数无法确定原版读取故障的指令位置。

分段探针 `e187b2b-native-prefix` 在同一存档上用原始机器码执行前四条图块头读取（`0x38`、`0x68`、`0x90`、`0xB8`）。四个截断版本的 3600 个工作组均通过 GPU fence。随后完整内核在同一批图块上读取未映射地址 `0xA0000`，系统错误报告确认访问类型为读取。需要继续区分后续读取及完整内核下的指令调度。

逐条读取探针 `e187b2b-native-loads` 在同一存档上通过了截至 `0x350` 的测试。增加 `0x358` 的 `LDG.E.B32 R17, [R0+0xC]` 后，首批 3600 个工作组读取未映射地址 `0xC0000`，系统报告确认是读取页错误。该指令读取绘制命令的 `colors.w`（Screen 覆盖表偏移）。上一个阶段读取同一结构里的 `colors.z`。本轮定位到首次触发故障的加载，地址异常的成因仍待实机验证。

合并候选 `e187b2b-native-paired` 将 `colors.zw` 改成一条对齐的 64 位读取。第 14 号档的 `0x358`、`0x398` 和 `0x3A8` 阶段通过。首个失败阶段移到 `0x3B0`，对应绘制命令的 `meta.z`，系统报告读取未映射地址 `0x20000`。这次故障发生在分段阶段，完整内核尚未出画。

六组相邻读取合并后的 `e187b2b-native-draw-reads` 通过了 `0x358` 和 `0x3A8`。下一段把原来的 `meta.zw` 合并为位于 `0x3B0` 的一条 64 位读取，`0x3B8` 为等待加载完成的空操作。该段报告读取未映射地址 `0xA0000`，后续阶段及完整内核未执行。这一帧共 12 条绘制命令，按有效命令索引计算，`meta.zw` 位于绘制缓冲的 `[0x503950058, 0x503950740)` 范围内。系统错误报告只给出故障地址和访问类型。

候选版 `e187b2b-ubo-draws` 让暴风雪内核通过常量缓冲索引绘制命令。反汇编确认 17 处绘制字段读取来自常量缓冲。Mac 用同一布局重放第 14 号档，90 帧 1280×720 逐像素一致，并验证了超过 409 条命令时切回既有合成路径。诊断日志分别记录首批图块合成完成与画面提交，用于 Switch 实机验收。

`e187b2b-ubo-draws` 的 Switch 日志确认第 707 帧完成 3600 个暴风雪图块合成并提交画面。`y05-01.s:4437` 后续采样出现 57–60 帧，完整合成约 12.8 ms，复用部分底图后约 6.6 ms。推进至 `4459` 后，帧中包含 3592 个暴风雪图块与 8 个其他图块。第 1044 帧仍成功提交，第 1045 帧读取未映射地址 `0x40000` 触发 GPU 页错误。系统错误报告确认读取类型，现有日志尚不能区分该帧的具体失败阶段。

扩展本地回归从第 14 号档推进至 `4437 → 4459 → 4477`，分别比较 180、900、180 帧，合计 1260 帧逐像素一致。候选 `e187b2b-ubo-deps` 为 17 条动态常量缓冲读取设置独立的地址与结果依赖槽，并在下一条指令前等待完成。机器码检查确认操作码和 DKSH 元数据保持一致。诊断版增加视频转色、各类图块合成和画面复制的 GPU 完成记录，以及每帧暴风雪图块和命令索引范围检查。该候选仍需实机验收。

`e187b2b-ubo-deps` 的实机复测已从第 14 号档推进到 `4529`，第 1687 帧读取未映射地址 `0x60000`。逐阶段 GPU 记录显示该帧四路 NV12 转色完成，用时 4.498 ms，暴风雪合成开始但未完成，画面复制尚未开始。扩大依赖等待的候选覆盖了全部 76 条变延迟指令，包括 17 条常量缓冲读取、16 条全局读取和数值转换等指令。仍需用实机验证其稳定性和开销。

`e187b2b-native-serial` 的本地回归从第 14 号档依次推进至 `4437、4459、4477、4494、4512、4529`，合计比较 2520 帧。在 `4459` 和 `4529` 各连续比较 900 帧，全部像素与既有合成路径一致。候选机器码只修改 56 组调度控制字，操作码与 DKSH 元数据保持一致。诊断版保留逐阶段完成记录，额外等待会影响实机帧率，性能结论需在稳定性确认后评估。

`e187b2b-native-serial` 已通过第 14 号档实机推进，日志到达 `y05-01.s:6330`，用户确认多个场景顺利运行。该次日志没有 GPU 队列错误，暴风雪全屏合成约 15.6–17 ms，四路视频转色约 4–5 ms，画面复制约 0.86 ms。后续性能候选将全屏 Screen 风雪层的参数读取压缩到每层 3–4 个字段，普通图片分支按需读取其余采样参数，逐阶段诊断等待限于首帧。

性能候选 `e187b2b-blizzard-fast` 沿用变延迟指令的依赖等待。Screen 分支先读取绘制标志和两个源偏移，有透明度混合时再读取不透明度。选入此分支的图层须覆盖完整 1280×720 画布，条件由图层数据判断，后续同类暴风雪自动复用。Mac 从第 14 号档推进六页剧情，共 2520 帧逐像素一致。候选已更新到实机诊断入口，GPU 耗时待新日志确认。

`e187b2b-blizzard-fast` 的实机日志到达 `y05-01.s:5960`，没有 GPU 队列错误记录。同页 `4459` 的合成耗时中位数从 16.927 ms 降到 13.403 ms，约减少 21%，新版帧率样本为 52–53。后段 `4921` 起的大暴风雪是两层 960×540 灰度雪幕，放大到 1280×720，合成仍约 23–31 ms，当时的帧率约 35–45，尚未命中对齐影片的优化条件。

`e187b2b-gray-storm` 增加了这类缩放雪幕的识别，验证不透明和灰度属性后，复用雾气的单通道双线性采样与 Screen 混合。参数与图块数据驱动选择，后续同类雪幕会自动复用。Mac 用通用逐像素合成核作参考，从第 14 号档覆盖 `4437、4459、4921、4939、5082、5318、5408`，1170 帧像素一致。原运动对照核在 `5318` 的本地软件 Vulkan 后端发生等待超时，通用参考核和新候选均完成该段回归。诊断 NRO 已更新，实际帧率待实机复测。

## 开场首次加载

`668912f` 把选择菜单预读移到开场标题准备完成之后，给厂商 Logo、雪景背景和按钮图预留共享队列的容量。标题资源可在警告画面和 Logo 期间就绪，进入鉴赏或剧情前仍会提前准备选择菜单。Mac 冷启动对照中，原调度在 3 秒观察窗口内缺少标题素材，调整后在警告阶段约 74 ms 就绪，选择菜单素材也在使用前就绪。

Switch 的 `d19e881` 采样日志确认主菜单雪景在警告画面阶段已准备完成。该次冷启动第一次进入标题时，主线程更新用了 34 ms，绘制用了 12 ms。旧版 `b728715` 的一次冷启动在同一阶段记录了 330 ms 的主线程更新。两组数字各对应一次实机启动。

## 动态 CG 加载和切换

- 158 项本地 H.264/Matroska 转码包括风雪叠加、动态 CG 和厂商 Logo。独立影片和内嵌影片在图像布局符合条件时通过 NVDEC 解码，deko3d 直接消费 NV12 表面。剧情风雪影片沿用后台首帧准备，合成保留原混合和时序。
- CG 鉴赏会提前准备当前选中项目的第一项。打开图片或影片后，沿最近一次翻页方向只预读一项相邻差分。确认时接管同一预读请求，改选和退出时撤销失效请求，切换沿用 250 ms 叠化。Mac 用原封包第 45 组动态 CG 走通了打开、正反切换、循环翻页和退出。
- `5ae8a07` 让具有完整轨道头的单轨静音 H.264/Matroska 内嵌影片直接初始化解码器。有音轨、头信息不全和其他格式沿用完整探测。在 Mac 上对照全部 158 个本地转码，尺寸、时长、采样 RGBA、PCM 和回绕首帧一致。在输入字节已读入内存的条件下，解码器打开耗时中位数从 18.28 ms 降至 0.09 ms，P95 从 34.05 ms 降至 5.01 ms。该测量只覆盖解码器打开，Switch 上整段切换的耗时待采样。

## 正文字体槽位

《雪女》单独映射剧本指定的正文字体槽位。槽位 `5` 优先使用游戏资源中的 Tahoma，其余槽位使用对白字体。普通对白在 720p 下使用与 WHJ2 一致的 26 像素字号。选定字体后，字形缓存和正文增量渲染沿用各游戏的通用路径。[共用运行时的字形缓存与正文增量渲染](runtime.md#界面与持久化)

## 验证方式

在仓库根目录用 `QLIE_GAME=whj6 sh ./build-switch.sh` 生成正式 NRO。正式构建默认关闭采样。加入 `QLIE_SWITCH_DIAGNOSTICS=1` 会生成独立采样版，Switch 日志写到 `sdmc:/switch/whj6/snow-probe.log`。通过 `WHJ6 SCENE` 定位剧情页，使用 `DEKO3D PRESENT` 对照影片首帧、GPU 合成及 `fog_tiles`。冷启动从完全退出游戏后重开，动态 CG 从已解锁的同组项目做连续正向、反向和快速改选对照。
